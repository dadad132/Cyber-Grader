How to run a building network audit

Check an office's Wi-Fi and network from the inside: the router's admin ports, devices that expose file shares, Remote Desktop, cameras or printers to everyone, UPnP, Wi-Fi encryption and signal, and latency. Results go straight into your account with a grade and a fix list.

Only audit networks you own or are authorised to test. The audit connects to devices on the local network (it doesn't change anything or try passwords), which can still alarm a network's owner if they didn't agree to it.

Before you start (once)

  1. {% if current_user %}You're signed in.{% else %}Create an account or log in.{% endif %}
  2. Go to Account › API access and click Create API key. Copy the key (it starts with cg_); it's only shown once. Audits don't use credits.
  3. At the site, connect your phone or laptop to the building's Wi-Fi (or plug the laptop into the network). Mobile data won't work.

Option 2: laptop (Windows, Mac or Linux)

  1. Install Python 3 from python.org if it isn't already (on Windows, tick Add python.exe to PATH).
  2. Download the audit agent (lan_agent.py, a single file).
  3. Open a terminal (Windows: Command Prompt) in the folder where it downloaded and run: 
    python lan_agent.py --server {{ server }} --api-key cg_YOUR_KEY --site "Company A office"
    On Windows and Linux the agent reads the Wi-Fi name, security and signal itself. Add --wifi-security WPA2 to set it by hand.
  4. It prints the grade and fixes, and a link to the full audit in your account.

No internet at the site? Use --output audit.json to save the results instead of uploading.

Inside vs the internet-facing side

The audit mostly checks the network from the inside: what one device on the Wi-Fi or LAN can reach. It also runs one outside check: the grader server, which is on the internet, looks back at this network's own public address and reports whether router-management ports (Winbox, the RouterOS API, Telnet, FTP, Remote Desktop…) are open to the whole internet. This is the single most important check for a MikroTik router.

It only ever checks the public address this audit is uploaded from, i.e. the network you're connected to, never anyone else's. Running the audit on your PC at the office won't test this (a device can't reach its own public IP from inside); it works once the grader is on a real server on the internet and you upload from the office.

Reading the results

  • Grade and score cover only what was measured. Anything the device couldn't check (for example Wi-Fi security on a laptop plugged into a cable, or internet exposure during a local test) is listed under Not checked and left out of the score.
  • Exposed to the internet: a router-management port open to the whole internet is the most urgent thing to fix; close it and allow it only from the LAN or a VPN.
  • Critical / high: Telnet or FTP open on the router, open (password-less) Wi-Fi, file shares or Remote Desktop reachable from the Wi-Fi, UPnP switched on. Fix these first.
  • Network segmentation findings list which device addresses exposed what, so you know which device to move to its own VLAN.
  • The audit sees the network from where the device is connected. Run it on each Wi-Fi (staff, guest) to compare them.

If something goes wrong

  • "Connect to the building Wi-Fi first": the phone is on mobile data or not connected to Wi-Fi.
  • "A valid API key is required": copy the key again from Account (create a new one if you've lost it).
  • Can't reach the server: check the grader address, including https://, and that the phone has internet through the Wi-Fi.
  • Every device shows as closed: some Wi-Fi networks isolate clients from each other (common on guest Wi-Fi), which is good. The audit then mostly sees the router.
